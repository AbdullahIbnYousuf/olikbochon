# Risk Register

Ratings are qualitative for planning. A “gate” means implementation or submission must stop until the mitigation is satisfied.

| ID | Risk | Current evidence | Likelihood | Impact | Mitigation / gate |
|---|---|---|---|---|---|
| R01 | Internet dependency | Starter metadata enables internet and its NLI cell uses a remote Hugging Face ID. | High | Critical | Attach pinned local artifacts; set offline flags and `local_files_only=True`; pass a Kaggle internet-off smoke test. |
| R02 | Hugging Face download failure | No model sources are attached; `pipeline` must resolve config/tokenizer/weights. | High | High | Never resolve remote IDs in final inference; verify manifest before model construction. |
| R03 | Python/library incompatibility | Local setup uses Python 3.14; Kaggle image and model cards may use different Python/Transformers versions. | Medium | High | Test in the exact Kaggle image; record versions; avoid unsupported APIs; attach offline wheels only if necessary. |
| R04 | Kaggle GPU memory limit | Version 3 uses length 512 and repeated fresh BanglaBERT phases on a T4-class GPU. | Medium | High | Use fp16, dynamic padding, batch 8/accumulation 2; on CUDA OOM discard all partial phase state and restart once from the original checkpoint at batch 4/accumulation 4; record peak VRAM. |
| R05 | Runtime over 9 hours | Unbatched NLI and excessive CV/ensembles multiply runtime. | Medium | Critical | Batch inference, benchmark full scale, cap folds/models, keep a linear/single-model fallback, require a runtime margin. |
| R06 | Label-direction mistake | Official labels are `0 = hallucinated`, `1 = faithful`; libraries often default to class 1 as positive. | Medium | Critical | Central label map; explicit metric labels/`pos_label=0`; unit tests with known synthetic arrays; verify model `classes_`. |
| R07 | Official metric ambiguity | Rulebook mixes “Macro F1” with “on ... label 0”; starter declares macro F1. Class-0-only thresholding selected 0.71 and collapsed to about 98% label-0 predictions. | High | High | Ask organizers for the exact evaluator/sklearn equivalent; report both objectives; default provisionally to macro-F1 OOF selection; keep 0.71 experimental and never recommend it without explicit binary-F1 `pos_label=0` confirmation. |
| R08 | Train/test leakage | Public download contains a CSV with the exact official test hash. | High | Critical | Explicit JSON allowlist; identify public roots by the 4k/1k files and quarantine every CSV below them; require a separate coherent competition root; never inspect test text. |
| R09 | Duplicate leakage | Public aggregate fully contains its train/validation files; synthetic near-duplicates may cross folds. | High | High | Use aggregate or subsets, never both; exact and near-duplicate grouping before splits. |
| R10 | Test-row inspection | Manual viewing/labeling is prohibited. | Low with controls | Critical | Metadata-only audit tools; no `head`, sampling, logging, plots, or error dumps containing test text. |
| R11 | Submission-format errors | Starter invents IDs if absent and does not validate exact output contract. | Medium | Critical | Fail on missing IDs; preserve duplicate or unique input IDs and exact order; require `id,label`, integer `{0,1}`, dynamic row/ID equality; independently validate macro, fixed-0.50, and experimental variants. |
| R12 | Missing model/tokenizer files | An incomplete Kaggle attachment can load partially then fail offline. | Medium | High | SHA-256 manifest for config, tokenizer, vocab, special tokens, weights, threshold, and preprocessing; fail early. |
| R13 | Public-leaderboard overfitting | Multiple generated thresholds and visible scores invite iterative threshold probing. | Medium | High | Predeclare local validation and strategy names; prohibit public-leaderboard threshold selection; use leaderboard only as a coarse pipeline sanity check; organizer clarification must determine the official objective. |
| R14 | Incompatible model license | BanglaBERT and its official normalizer declare CC BY-NC-SA 4.0; the user confirms this is a noncommercial university student competition. | Low for private competition use; higher for publication | High | Proceed privately with attribution and notices. Keep base and derived weights private; confirm ShareAlike, noncommercial, and organizer requirements before any public weight publication. |
| R15 | Repository data leakage | Data, ZIPs, outputs, credentials, and weights must never enter Git. | Medium | Critical | Keep ignore rules; stage explicit docs/code paths; audit `git diff --cached --name-only` and tracked file sizes before every push. |
| R16 | Wrong public dataset version | Directory/request says 20k, but current dataset has only 5k distinct labeled rows. | High | Medium | Confirm intended Kaggle dataset/version with the team; record dataset ID/version/hash; never fabricate or silently merge duplicates. |
| R17 | Undocumented public provenance/license | Labels empirically align, and the user approved `abidur14004/new-dataset` for Version 2 in this university event, but metadata remains empty and the license is unknown. | Medium | High | Declare the user approval and Kaggle identifier, cite the source, retain the uncertainty, limit use to the approved event scope, and never imply organizer provenance without evidence. |
| R18 | Context-regime imbalance | Many labeled records use null-like context; closed-book and grounded tasks differ. | High | High | Normalize context consistently; stratify/report by `has_context`; test specialists only with enough data. |
| R19 | Threshold overfitting and class collapse | Choosing and reporting a threshold on the same OOF predictions inflates the selected score. Class-0-only optimization approaches the all-zero class-0 F1 baseline of about 0.6253. | High | High | Label all full-OOF-selected scores tuning estimates; report separate nested macro and class-0 estimates; default to macro F1; warn above 90% predicted-class share; keep fixed 0.50 as a reference. |
| R20 | Model artifact size creep | Multiple framework variants, optimizers, and ensembles can waste the 50 GB allowance. | Medium | High | Package only inference weights/tokenizers; exclude optimizer/TF/Flax/ONNX duplicates; audit total size. |
| R21 | Preprocessing drift | BanglaBERT requires a specific normalizer; train/inference versions may diverge. | Medium | High | Vendor/pin permitted normalization code, test golden synthetic strings, include hashes and license. |
| R22 | Hard-coded test assumptions | Starter has a fallback ID range; held-out rerun may differ in rows/order/IDs. | Medium | Critical | Dynamic schema/ID handling and tests with varied synthetic row counts/orders/types; never encode observed test values. |
| R23 | Final-refit calibration shift | Version 2 freezes a threshold on public validation, then refits on validation and official rows too. | Medium | Medium | Keep the threshold frozen, document that calibration can shift, create a fixed-0.50 reference, and prohibit official-sample or leaderboard retuning. |
| R24 | Embedded-runtime drift | Kaggle notebook imports cannot see repository `src/`, so copied helpers can silently diverge. | Medium | Critical | Generate one deterministic ZIP from canonical modules, embed its SHA-256 and per-file manifest, test synchronization, and import it in isolation before committing. |
| R25 | Normalizer dependency drift | Official code imports compiled `regex`, `emoji`, and ambient `ftfy`; Kaggle versions are not stable. | High | High | Support only the audited default call, exclude unused optional branches, bundle pinned pure-Python `ftfy`/`wcwidth`, and fail the frozen 79-case startup digest before real data loading. |
| R26 | Optimistic V3 OOF selection | The same official OOF predictions compare arms and tune the selected threshold. | High | Medium | Label both outputs optimistic model-selection/tuning estimates, report fixed-0.50 metrics, freeze rules in code, and never use leaderboard outcomes to revise them. |

## Questions that block higher phases

1. What exact implementation does the official evaluator use: class-0 binary F1 or two-class macro F1?
2. Is `abidur14004/new-dataset` the intended external dataset/version despite containing 5k rather than 20k unique labeled records?
3. What license and provenance authorize use of that public 5k and redistribution of models trained on it?
4. If organizers require public model publication, what attribution, license, and visibility rules apply to the BanglaBERT-derived checkpoint?
